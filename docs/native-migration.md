# 原生 macOS 桌面层迁移

决策日期：2026-09-22。状态：**旧桌面源码与构建入口已移除；原生功能与正式发布尚未全部完成**。
本文件是 [PLAN.md](../PLAN.md) N1–N5 的边界与验收依据。`native/` 与
`scripts/build-native.ts` 提供唯一桌面 `.app` 构建；旧 `app/` 已删除，旧发布流程已停用。
当前功能、命令和缺口见 [原生开发说明](../native/README.md)，实际结果见
[第一版验收记录](../baselines/native-0.1.0.md)。下列架构与验收要求是完整迁移目标。

## 已确定的架构

**SwiftUI + AppKit 替换 Tauri、Rust 桌面层和 HTML/TypeScript WebView 界面；
保留 TypeScript/Bun Core 与独立的 Pocket Motion。** 不使用 Electron，不以全部
Swift 或移除 Bun 为后续目标。图片、GIF、视频生成是产品核心能力。

```text
SwiftUI / AppKit 原生桌面层
  界面、窗口、菜单栏、快捷键、剪贴板、AX、粘贴
  加密历史、Keychain、设置、订阅与包安装、更新、Core 进程管理
        │ 本地任务协议（从现有 JSON lines 兼容接入）
TypeScript / Bun Core
  推荐、模型调用、动作、卡片决策与编排、渲染调度、GIF 编码
        │ 引擎适配
Pocket Motion（engine.json 固定版本）
  composition 构建、文字度量、画面与动画帧渲染、视频编码链路
```

Core 是 Peesuto 的业务层；Pocket Motion 是独立的渲染项目。当前引擎依赖 Bun
进行构建、执行 JavaScript 画面描述、驱动 WASM 和任务调度，原生 UI 不消除这些依赖。
引擎底层的 Rust/WASM 不属于被替换的 Rust 桌面层。保留后台运行时不要求任何界面
WebView。应用界面不直接依赖引擎内部模块，渲染适配继续收敛在 Core。

## 范围与当前状态

| 范围 | 当前实现 | 目标 |

| 系统能力 | Swift/AppKit 已实现采集、存储、AX、快捷键与粘贴模块 | 补齐跨应用、多屏、权限等完整验收，保留隐私约束 |

| 图片/GIF | 已接入动作与结果视图 | 原生预览、复制/粘贴、导出；保持既有输出质量 |

当前 macOS 最低版本为 13.0（2026-09-23 由 12.0 提高：随包 Bun 二进制的 minos 为 13.0，
另可使用 SMAppService 登录项，决策见 [PLAN.md](../PLAN.md) §5）。使用更新的 API 要提供

`native/` 已创建 SwiftPM 工程与测试；`bun scripts/build-native.ts --engine <prepared-pin>`
打包完整应用。`swift build` 单独运行不产生包含 Core/引擎的 `.app`。

## GUI 方向

以下为实现起点，具体尺寸与布局通过真实原生交互验证后调整：

- 已实现默认 ⌘⌥1/2/3 将当前剪贴板文字直接生成图片/GIF/视频；设置可直接按键
  录入或清除停用，保存后生效。该入口不要求先打开历史面板，仍排除受保护内容。
- 快捷键任务使用不激活应用的状态浮窗。完成后只在原目标应用、窗口、输入控件、
  选区和内容仍可验证且权限可用时自动粘贴；否则仅复制。若任务期间用户复制了新内容，
  保留新剪贴板，不自动覆盖或粘贴，结果可再手动复制、粘贴或导出。
- 一个日常面板：搜索、稳定的历史列表、独立推荐项；选中内容后再显示相关动作。
  推荐完成不打乱正在浏览的历史，不因异步结果替用户更换当前选择。
- 动作结果在同一面板预览，可返回原选择；保留复制、粘贴、导出和失败重试入口。
  PNG/GIF/视频预览体现真实输出，不用与最终文件不一致的占位效果代替。
- 菜单栏保持少量入口：打开面板、设置、必要的状态控制、退出。完整动作列表放在
  面板的动作菜单中，支持键盘调用，避免把菜单栏变成说明文档。
- 设置按用户任务组织：通用、历史与隐私、AI 与动作、账户与内容、进阶。
  Provider 的高级参数逐步展开；Core 路径、sidecar 模式、原始日志只供开发诊断。
- 保留键盘优先操作与清晰的焦点：搜索、方向键、回车确认、Escape 返回/关闭。
  权限拒绝时历史和复制仍可使用，清楚说明受影响的功能。
- 中文、英文和跟随系统即时生效。迁移 `settings.json` 的 `language` 值
  `system` / `en` / `zh-CN`；不翻译剪贴板内容、生成结果、自定义名称/提示词和协议值。

## 数据与系统能力兼容

- 保留应用标识 `com.peesuto.desktop`、Application Support 目录和 Keychain service。
  保留历史密钥账户 `pocket-paste/history-key` 与现有 Provider 凭证引用。
- 兼容既有 SQLite schema、AES-256-GCM 数据格式（12 字节 nonce 后接密文与认证标签）、
  加密图片和缩略图。使用合成数据副本和已知测试密钥验证双向读写，不能拿生产数据
  试验不确定的转换；保持标识不等于自动保证 Keychain/TCC 授权继续有效。
- 迁移保留期、排除规则、快捷键、Provider、动作、扩展包、语言等设置。新旧格式若
  必须转换，应有版本、备份、可重复执行的迁移与回退方案。
- 缺密钥、访问被拒或解密失败进入锁定/错误状态，不自动创建新库覆盖旧数据。
  清空历史、重新开始等破坏性操作保持明确的用户确认。
- 迁移剪贴板去重、Concealed/Transient 排除、密码管理器黑名单、密码框短路，
  以及焦点恢复和粘贴降级。验证多屏、全屏应用、输入法和快捷键冲突。
- 旧版与原生版不得同时采集或写同一生产目录；开发验证使用隔离目录与测试密钥。
  旧源码仅从 Git 历史查阅；旧发布产物不在本次清理范围。

## Core 协议与生命周期

保留 [现有协议](daemon.md) 与 CLI。当前协议仍串行服务；`run-action`/`render`
通过 `events: true` 选择接收 accepted/running/completed/failed 生命周期事件，
最终响应格式不变，不发送伪百分比。没有细分渲染进度、单任务取消命令或能力协商。
原生客户端已支持超时、重启配置恢复、终止整个 Core 进程组的取消；idle timer 已在
请求执行期间暂停、完成后重启。以下是完整目标要求，不能视为协议已全部实现：

1. 协议版本/能力协商、请求 ID 与明确的任务状态；错误使用稳定代码，由原生层本地化。
2. 进度事件与最终结果可区分；先定义消息格式和兼容测试，再接 UI，不向旧协议发送
   未实现命令。无事件的请求/响应模式继续用于 CLI 和既有集成。
3. 界面/历史不等待 Core；按需启动、任务间复用、无活动任务时空闲退出。活动任务不能
   被空闲计时器终止；每次重启先恢复配置和凭证，日志不得记录凭证与用户内容。
4. 长渲染不阻塞轻量请求；必要时隔离渲染工作进程，但同一引擎资源树的构建必须串行，
   或使用真正独立的构建资源。仅创建不同输出目录不能消除共享生成文件的竞争。
5. 取消和超时必须终止对应实际工作、清理临时产物/子进程，并丢弃迟到结果。配置快照
   与离线切换的行为要明确，离线后不得启动新的外发请求。
6. 崩溃后保持历史可用，提示受影响任务并允许重试；不得自动重复粘贴或无提示地重复
   可能产生费用的模型调用。Core 不负责模拟键盘粘贴。

## 核心输出与性能

当前模板层提供文档、引用、代码、数据、列表、对话、表格、对比 **8 类，每类 2 变种**。
原文与结构本地解析，Jev 仅选受限的兼容模板/变种/动效；原生结果支持换风格与输出格式。
其余 4 类仍待后续实现。见 [模板边界](templates.md)，不能将旧 DSL 夹具通过等同于
所有新模板的视觉与保真验收通过。

PNG/GIF 沿用现有 composition 和夹具，不能为迁移方便缩减为少数固定原生卡片。
视频内置动作 `paste-video` 已实现，通过 Pocket Motion 和本机 ffmpeg 生成 MP4。
编码器按显式 `PEESUTO_FFMPEG_PATH`、PATH、macOS 常用 Homebrew 路径查找；缺少时
提示安装，不自动下载安装，也未内嵌进 `.app`。正式分发、细分进度和完整视频场景验收
仍待完成，不能把代码接入等同于所有目标应用均已验证。
Pocket Motion 的帧确定性与 MP4 容器字节一致性不同，验收须分别描述，不能混为一谈。

以相同机器、输入、分辨率、帧率与缓存条件记录：

- 面板首次/再次打开的响应；Core 冷/热启动；PNG/GIF/视频冷/热输出耗时。
- 应用、Core、渲染和编码子进程的整体内存足迹，区分空闲与峰值，避免只看 UI 进程。
- `.app` 体积、安装后的引擎副本、缓存与输出占用；可共享页或 APFS 克隆不重复解释
  成独占物理占用。磁盘体积也不能当作运行内存。
- 长任务中的历史搜索与轻量请求响应、取消延迟、退出后残留进程。

现有 GIF 路径先缓存全部缩小的 RGBA 帧再编码，帧缓存、采样策略和资源释放是优化
对象。保留 Bun 意味着仍需分发运行时；不承诺“原生 UI 就会让整个包或渲染快数倍”。

## 源码切换与正式交付条件

旧桌面源码、专用锁文件/配置、WebView 前端与旧发布流程已删除，`native/` 是唯一入口。
`bundle-sidecar` 默认暂存到 `native/.bundle`；CI 已切换原生测试、编译与 bundle 冒烟。
手动工作流只产出验证 ZIP，不发布版本或更新元数据。引擎 Rust/WASM 与用户数据保留。

源码移除是明确的产品决策，不能代替尚未完成的验收。N1–N5 继续按 [PLAN.md](../PLAN.md)
推进；正式交付之前仍须满足：

- 原生 `.app` 独立运行，无需仓库、系统 Bun、开发服务器；签名、公证覆盖所有嵌套
  可执行文件。界面与构建入口不依赖 Tauri 或 WebView。
- 六个内置动作（含视频）、历史、权限、焦点、Provider、订阅/包管理及中英文
  完成真实应用验证；服务端未部署的部分使用明确标注的测试服务，不声称已上线。
- 旧数据、配置与 Keychain 兼容测试通过；隐私清单重跑；已有 Core 与帧摘要测试继续通过。
- 选择并验证原生更新方案（建议 Sparkle）。旧桌面从未发布过版本，没有需要桥接的
  已安装用户或旧更新元数据；完成原生分发前不启用发布工作流。
- 实际打开交付路径中的 `.app`，核对版本、语言设置、动作输出与无开发环境启动，
  记录结果。编译、合成测试和预览截图均不能替代完整的真实应用验收。

当前保留现有引擎 pin，旧桌面源码已删除；尚未发布或切换正式更新链路。账户/扩展包 GUI、
动作编辑、高级设置、细分进度与并发调度、正式更新与签名发布仍未完成。
